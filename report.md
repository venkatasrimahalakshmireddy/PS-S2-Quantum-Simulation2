# Phase 1 Benchmark Report — PS-S2

## Objective
Compare first-order Trotterized TFIM dynamics on participant-defined Processor A and Processor B connectivity graphs. Routing overhead is estimated by comparing routed CX count against an unconstrained transpilation; because SWAPs are decomposed into CX gates, the SWAP-equivalent figure is an estimate (excess CX / 3), not a direct count of explicit SWAP instructions.

## Experimental settings
- Hamiltonian: \(H=-\sum_{i=0}^{2} Z_iZ_{i+1}-g\sum_{i=0}^{3}X_i\)
- Initial state: \(|0101\rangle\)
- Final time: \(t=2.0\)
- Fields: \(g \in \{0.5,1.0,1.5\}\)
- Trotter steps: \(n \in \{1,2,4\}\)
- Shots: 4096; transpile optimization level 1; seed 42
- Synthetic noise: 1-qubit depolarizing p=0.001, CX depolarizing p=0.005, readout p=0.01 on both processors.

## Detailed Interpretation and Analysis

### 1. Does Processor B reduce SWAP overhead for nearest-neighbour TFIM interactions?
No. For the 4-qubit linear nearest-neighbour TFIM chain, both Processor A and Processor B exhibit zero routing CX overhead (`routing_cx_overhead = 0`) and zero SWAP-equivalent overhead (`swap_equivalent_overhead_estimate = 0.0`).
- Processor A contains a linear path spanning 4 vertices: `0 — 1 — 3 — 4`.
- Processor B contains multiple linear subgraphs of length $\ge 4$ (e.g. `0 — 1 — 2 — 3 — 4`).
Because the transpiler finds an exact subgraph isomorphic to the 1D problem interaction graph in both processors, zero SWAP operations or routing CX overhead gates are inserted.

### 2. How do depth and CX count change with Trotter steps?
Depth and CX count scale strictly linearly with the number of Trotter steps $n$:
- **$n = 1$**: CX count = 6, depth = 16.
- **$n = 2$**: CX count = 12, depth = 27.
- **$n = 4$**: CX count = 24, depth = 49.
Each additional Trotter step adds 1 layer of 3 $R_{ZZ}$ interactions (each decomposed into 2 CX gates, contributing $3 \times 2 = 6$ CX gates) and 1 layer of single-qubit $R_X$ rotations.

### 3. How does noisy $\langle Z_0 \rangle$ differ from the ideal estimate and exact reference?
- **Trotter error dominance at low $n$**: For $n=1$ and $n=2$, discretization error dominates over noise. For instance, at $g=1.5$, both ideal and noisy values have large absolute errors ($\approx 1.05 - 1.07$) relative to the exact matrix-exponential reference.
- **Noise / fidelity trade-off at higher $n$**: At $n=4$, Trotter discretization error drops sharply (ideal error drops to $0.0026$ for $g=1.5$ and $0.0117$ for $g=1.0$). At this point, the physical depolarizing noise and readout error become noticeable, slightly attenuating the expectation value toward 0, though the estimate remains close to the exact analytical value.

### 4. Explain why the larger processor (Processor B) does not improve the result
A larger qubit topology only yields routing benefits when the problem graph cannot be embedded directly into the smaller hardware topology without SWAPs. Since the 4-qubit 1D TFIM already embeds into Processor A with zero SWAPs, Processor B's extra qubits and higher connectivity do not reduce gate counts or depth. Under identical noise models and transpiler seeds, the circuit structure and resulting measurement distributions on both processors are identical.

### 5. Limitations
The noise model utilized is a synthetic model consisting of uniform single-qubit depolarizing error ($p=0.001$), two-qubit CX depolarizing error ($p=0.005$), and symmetric readout error ($p=0.01$). This benchmark isolates topological routing and discretization effects under controlled conditions, and does not model physical hardware imperfections such as coherent errors, spectator crosstalk, frequency collisions, or drift.
